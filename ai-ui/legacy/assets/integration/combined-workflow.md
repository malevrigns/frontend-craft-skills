# 两个 UI Skill 的联合工作流 v2.0

## 工作顺序与责任

1. **Brief（ai-ui 负责）**：产品目标、目标用户、3 个核心场景、平台、关键路径、可测成功指标；记录所有假设。
2. **Design（ai-ui 负责）**：一个审美方向、可读性/对比度/密度策略、信息架构、移动/桌面布局、token 规范。输出 `DESIGN.md`。
3. **Interaction（app 负责）**：选择 1–3 个直接改善核心任务的交互，写出 `INTERACTION.md` 的事件/状态、打断与失败恢复、键盘触屏等价操作。
4. **Prototype（联合负责）**：先把一个真实任务做通（包括 Loading/Empty/Error），再扩展页面。Web 直接用 DOM 组件；Expo 原生必须有平台适配。
5. **QA（联合负责）**：320/390/768/1440 断点，键盘/触屏，暗色与减少动态效果，焦点与撤销，程序状态一致性；用截图回看密度和层级。
6. **局部迭代**：每轮只处理 1–2 个最大问题，保留已验证的业务行为。记录 `issue → 修改 → 验证`，而不是整页重画。

## 常见冲突裁决

- 审美规则与可用性冲突：无障碍、数据真实性、任务完成优先。
- 两个 Skill 都定义按压动画：仅应用 app 的交互实现；ai-ui 的纯视觉静态样式不叠加第二套 transform。
- 重复的 token：`ai-ui/assets/tokens.json` 是联合项目视觉主源，`app` 保持镜像；安装脚本检测差异，不覆盖用户自定义 token。
- 切换到 iOS/Android：只复用 token 的语义与业务状态机；浏览器代码不直接导入 React Native。
- 流行审美（禁紫色、禁系统字体）与品牌表达冲突：品牌、文字可读性和上下文优先；lint 的品味规则仅为人工复核警告。

## 交付格式

`BRIEF.md` / `DESIGN.md` / `INTERACTION.md` / 可运行原型 / `QA.md`。每个文件有版本与关键假设。不能写“测试通过”除非执行验证。
