# First Impression Architecture — 首屏注意力与可信转化

## 设计目标
目标用户在**快速浏览**而非仔细阅读时，能看见一个与其需求相关的具体价值和可做的下一步。视觉冲击须源于内容的独特性、形式秩序和可信度；不能把“注意力”理解为最大字、最多视频、极强光晕。

## 注意力四件套
1. **Hook / 首视锚点**：最先吸引注意的东西。可以是实际产品状态、核心媒体、一个具有情境的品牌动作、数据异常或编辑式排版。关联产品利益而非纯装饰。
2. **Promise / 价值说明**：用具体结果和使用场景说明“是什么、为什么有用”，避免泛称“重新定义未来”“让每次增长清晰可见”。不知道真实收益时使用描述性事实，不乱写增长数字。
3. **Proof / 可信证据**：真实产品演示、可验证案例、真实数据或明确标注的模拟样例。若完全没有证据，明确 `none-yet`，不要制造假评价/假数量。
4. **Action / 首要下一步**：在首屏能辨识、行为可信的主要操作；CTA 文案要描述结果。可以是“查看工作流”、“试用 Demo”、“添加第一个项目”，不是所有场景都写“开始使用”。

## First Impression Contract (FIC)
```text
Intent             此屏的用户需要完成什么？
5-second read      产品/任务是什么？价值是什么？下一步在哪里？
Signature          一句话描述此产品独特的视觉记忆点
Dominant anchor    只能一个，必须绑定设计规格中的组件 id
Attention budget   主锚点 1 + 次级不超过 2；品牌/素材/CTA 不能各抢第一
Proof             来源、验证状态、是否 Demo
First action       与交互规格共享组件 id、行为与目的地
Small-screen       320×640、390×667 的独立构图，不是桌面缩小
No-JS + fallback   背景媒体错误/禁动画仍能阅读与操作
```

## 按页面模式确定“第一眼”
- `persuade`（营销）：识别目标客户、价值与差异，展示产品/真实质感，并给出单一 CTA；英雄区应有记忆点。
- `operate`（Dashboard / App）：用户登录后先看到最重要的**当前状态、异常或决策**，主锚点通常是任务/信息，不是巨幅宣言。易扫视和行动效率比炫耀优先。
- `read`（文档/帮助）：立即知道当前话题、导航路径和第一段有效信息；禁止全屏装饰抢走阅读。
- `experience`（作品/沉浸）：作品本身承担锚点，导航克制，交互清晰可撤销。

## 4 种视觉签名来源（混搭有理由，不要机械套用）
- **Product proof**：真实 UI 演示 / 确切使用结果 / 局部放大，让产品成为焦点。
- **Editorial framing**：产品专属语气、标题节奏、比例与留白，建立识别度。
- **Material encounter**：可感知的真实物体质感、光线、对比和层次；材质不是泛光、不是玻璃越多越好。
- **Data artifact**：任务关键数据 / 正确图表 / 实用预警；适合工具产品，但须保证数值语义真实。

## 构图执行规则
- 主锚点含独立的尺寸、位置、对比、层次和响应式规则；如果只是填了 `focalPoint` 字段但没落实到场景组件，不算完成。
- 视觉焦点的重量来自大小、对比、图形细节、视线方向、隔离留白共同作用，而非盲目放大 200%。
- 主要操作应在目标宽度内容易定位。不要把首屏变成滚动测验；但对操作工作台不用强行“一屏装下全部”。
- 动画不妨碍首次理解：JS 失效时可读，核心内容默认可见；入口视觉只允许少数重点动作，特别注意 prefers-reduced-motion。
- 先收集可用的、合法的素材证据，再设计图层；不允许用胡乱生成的数字背书提高信任感。

## 反模式（出现须说明合理性）
统一三卡片、假装科技的光晕、无端 Glassmorphism、千篇一律的紫渐变、内容不相关的英雄视频、仅有口号没有产品图、两排彼此竞争的 CTA、不可读的小字号、将 Dashboard 变成营销首屏、伪造“10,000+ 用户”。不要把任何单一色彩/形状作为绝对禁令；反对的是不经过设计决策的默认套路。
