# First Viewport Review — 验收首屏，而非验收 CSS 是否存在

## 视觉检查需在真实渲染后进行
- 保存 1440×900、768×1024、390×844、320×640、390×667（短屏）截图，含首屏全部结构；若适用，保存 dark、低速媒体/静态回退、reduced motion 状态。
- 在 25% / 12.5% 缩略图下看一眼：**是否仍有单一可识别的焦点？** 各个按钮是不是同时抢镜？这不是 WCAG 检查，而是构图感受评估。
- “五秒读懂”测试：不告诉评审产品简介，给他们看五秒，再问（1）它做什么/当前任务是什么（2）为何对你有用（3）下一步点哪里。记录原话、是否理解、样本数量。**没有真实被试时只能做启发式自检，不能宣称五秒用户测试通过。**
- 看品牌独特性：遮住 Logo/品牌字，此页面是否仍会被误认为任意其他 SaaS？若是，检查素材、视觉特征、内容真实性，而非单纯增加花纹。
- 看证据：任何社交证明与收益百分比是否有来源；模拟数据必须贴 Demo 标签。
- 看行为：CTA 是可按的，且触发有真实结果，不用假成功替代。
- 看响应式：主锚点在 320px 不可挤掉价值说明与主动作；短屏需要内容可滚动，不用“禁止滚动”遮住 CTA。

## 审查维度（1–5，需证据；不自动打通过）
1. **Immediate clarity**：首屏承诺/任务能否清晰辨认。
2. **Focal hierarchy**：视觉主锚点唯一且具有产品关联。
3. **Signature**：是否有真正产品专属视觉记忆点。
4. **Proof/trust**：真实可信，没有伪造指标和伪成功。
5. **Craft**：字形、字距、图文比例、层次、光影、像素边界。
6. **Responsive**：极窄/短屏下可读、主任务可继续。
7. **Interaction**：首个动作可信，状态/反馈/恢复可见。

## 缺陷日志格式
`{viewport, observedDefect, impact, rootCause, fix, screenshotBefore, screenshotAfter, verified}`。记录前三个缺陷，先修复最严重的 2 个；如果当前没有浏览器/视觉工具，写 `unverified` 而不是给高分。

## 注意
`node validate-spec.mjs` 和 `validate-first-impression.mjs` 只能检查 JSON 字段、一致性、资源引用和数字范围，**永远不能证明用户喜欢该画面或转化率提高**。界面必须在真实浏览器或对应原生设备中验收。
